# 统一会话引擎

> `TransferSessionRegistry`（会话注册表）、协议适配器（`service/transfer/adapters/`）与三类注册表（设备来源 / 传输方式 / 设置分组）的实现细节。
>
> 主文档 `docs/ARCHITECTURE.md` §4.9 保留概述；Repository 层的协议 I/O 与适配器事件来源见 `repositories.md`；
> 后台长时任务与通知编排见 `background-transfer.md`；MTA 协议层见 `mta.md` 与 `docs/mta/MTA_PROTOCOL.md`。

`entry/src/main/ets/service/transfer/`

统一会话引擎把六条传输路径（LocalSend 发送/接收、MTA 发送/接收、Web 分享下载/上传）的会话与待确认请求收敛到**唯一的会话注册表（SSOT）
**，协议差异下沉到**协议适配器**。统一会话建模「用户可见的一次有界传输活动」，与协议层会话/授权解耦。

> 传输抽象说明：MTA 是第二个传输实现，暂不抽取统一传输提供方接口；
> 新增第三种传输时按 MTA 模式提炼（能力声明加事件前缀隔离），契约测试会拦截单向改动。

## 1. 核心模型与不变式

- **唯一事实源**：`TransferSessionRegistry` 持有会话表，提供创建/追加/整体替换文件清单/进度/状态/终结/取消/重试/查询/终态回收；
  UI（任务、通用详情页）、后台长时任务与通知聚合、批量操作一律从注册表读取。取
  消/确认/拒绝/重试动作按适配器能力声明分发（`canCancel` / `needsConfirm` / `canRetry`）：
  声明不适用的动作为空操作，不改状态、不调用适配器；Web 下载批次/上传均声明 `canCancel=true`，结束任务时同时终止对应协议响应/会话
- **文件清单的来源与回填**：会话创建期的文件清单可来自协议声明（如互传接收在下载前只提供主文件名与文件数量、总大小，不含逐文件清单）；
  下载/解压落盘完成后由适配器以真实结果**整体替换**该清单（`setSessionFiles`：会话存在且非终态时按描述符重建逐文件条目、保留其携带的 `path`、
  重算会话总字节后发布一次变更通知；会话不存在/已终态/清单为空一律空操作，与「终态不改写」约定一致）。回填源是本次落盘的真实逐文件元数据
  （名称/大小/真实类型/磁盘路径），使任务详情的文件条目数与任务列表的文件数量文案等于真实接收结果，成功场景不再残留单一「主文件名」占位条目、
  也不再因缺少路径显示「内容不可用」
- **成功归档的路径前置条件**：文本消息会话成功终结前，至少一个文本类文件必须已记录最终 `path`——路径是历史只读态详情页
  读取正文的唯一来源，内存中的展示描述符只覆盖终态可见窗口。注册表 `finish` 成功分支以 `hasPreviewableTextPath` 记录缺失诊断；
  失败/取消/拒绝不要求路径（这些终态没有交付正文）。各协议的完成信号与路径写入时机见 §6
- **传输模型**：`dataFlow`（outbound/inbound）× `initiatedBy`（local/remote）两个正交维度；进度支持字节级与离散阶段两种口径，容忍文件集增量追加导致的**分母增长**（不回跳、不据此误判完成）
- **发送准备阶段与准备进度口径**：LocalSend 发送在开启「创建校验和」且存在缺失 hash 的文件时，会话创建后即进入**准备态**——
  复用 `stage=active` + 阶段文案「正在计算校验和」，不新增阶段枚举（避免扩散到徽标/聚合/历史映射等多处分支）。
  `TransferSession` 新增仅承载准备字节的 `@Trace prepBytes` / `@Trace prepTotalBytes`，与传输进度 `bytesSent` / `totalBytes`
  **严格分离、绝不混用**（二者是不同量纲，混用会导致转入传输时进度无法回退）；纯函数 `isPreparing(session)`
  （`!isTerminalStage && prepTotalBytes > 0`）判定准备态。注册表 `setPrepProgress` 写入准备进度（已哈希字节单调不回跳、刷新活动基准并发布变更通知）、
  `clearPrep` 在转入传输前清零，`finish` 终态时清零准备字段；后台聚合 `deriveOverall` 对准备态活跃会话以准备进度计入字节汇总（通知展示真实推进而非 0%）。
  任务行（`rowHasByteProgress` / `rowPercent`）与详情页（`hasByteProgress` / `percent`）的字节进度判定与取值在准备态改以准备进度为准
- **校验和批次编排与准备期取消**：校验和计算以**共享 `items` 数组引用**为键的在途批次编排（`SendRepository`）——同一批内容向多台设备发送只计算一次，
  后到参与会话加入同一批次并即时获得当前进度（不重复计算）；单文件失败记空校验和留痕后从本批剔除并计数，不可读文件提前退出发送链路。
  Rust 按块经 `checksumProgress{cancelId,hashedBytes}` 事件上报该文件累计已哈希字节（可丢弃事件，分母由 ArkTS 侧按文件大小提供），
  ArkTS 汇聚层写回会话前做节流（同值不写；百分比变化不足 1% 且间隔不足约 200ms 合并）。准备期取消经统一取消分发复用：
  注册表 `cancel` → `finish(cancelled)` → 适配器准备取消回调 → `nativeCancelHash` 立即中止哈希，且不发起任何网络发送；
  完成后按路径把共享 `items` 的 hash 回填各参与会话的文件副本并以 `setSessionFiles` 刷新清单（保持 `fileId` 不变，发送链路据此携带 sha256）
- **活跃口径**：仅「进行中」会话计入活跃传输——后台长时任务申请与保持、实况进度通知均只统计已进入传输的会话，
  待确认与终态不计入；`allFinished` 表示「全部会话均已终态」（待确认不算完成，避免仅有待确认时误发终态通知）。
  与之区分，**任务入口数量口径**为**非终态**（进行中 + 待确认）：`getUnfinishedCount()` 是任务入口角标的唯一来源
  （`MainTabViewModel.activeTransferCount`），面向「用户待处理任务量」，与面向「后台保护」的活跃口径相互独立
- **会话动作口径**：`resolveSessionActions(stage, capabilities, isText)`（`model/transfer/TransferSession.ets`）的任务列表行与详情页共用唯一判定——
  待确认且 `capabilities.needsConfirm` → 可确认 / 可拒绝；非终态且 `capabilities.canCancel` → 可取消（该规则天然覆盖发送任务「等待对端接收/确认」阶段，
  该阶段 `stage=active`）。详情页 `SessionDetailViewModel` 与列表行 `TransferCenterViewModel.rowActions` 均调用该函数，并按同一 if/else 顺序呈现一组动作
  （文本消息会话以「关闭 / 复制」标签承载确认语义，可用性判定与文件会话一致）
- **协议键过滤查询**：`listActiveSessionsByProtocolKeys` 按协议键集合返回未终结会话（含待确认、排除终态），供协议总开关关闭前的
  二次确认弹窗列出将被中断的传输明细；范围口径：LocalSend = `localsend-send`/`localsend-receive`/`web-download`，MTA = `mta-send`/`mta-receive`
- **条目必须可进入（硬性不变式）**：任务行序列构建后执行可解析性校验（纯函数），凡不能解析为「实时会话或历史记录」的条目一律剔除（零展示）
  并输出结构化诊断（会话标识〔即条目身份〕/ 是否持有实时会话对象）；列表构建与详情加载同源于「注册表 + 历史」，不引入第三来源
- **唯一通知入口**：复用 `AppCore` 变更总线（`subscribe`/`notifyChange`）发布 UI 变化；
  接收完成的交付信号（相册保存与文本展示）仍经 `peekRecv*`/`consumeRecv*` 一次性读取接口由 AppService 暴露给 ViewModel

## 2. 生命周期与终态

- **终态判定权归适配器**：协议可能无结束信号，适配器可用静默窗口、无活动超时等策略；注册表只负责终态之后的**可见窗口**（成功
  3s / 失败与取消 5s）、归档与回收，同标识重建时取消挂起的回收定时器（不被旧定时器误删）
- **发送侧无进展兜底终结**：发送方向（outbound）非终态会话由单一节流看门狗巡检（默认 10 秒一轮），连续无进展（无字节进度、无阶段/文案更新、无文件集追加）超过固定阈值（默认
  60 秒）即按失败终结并记录可诊断的错误信息与错误码；判定抽为纯函数并提供可注入当前时刻的检查入口。**不设会话总存活上限**——只要持续有进展，超大文件长传输绝不被终结。
  看门狗仅在存在发送方向非终态会话时运行，无活跃发送会话即停止，注册表重置时清理其定时器与活动时刻表；与入口收口兜底幂等（首次到达的终态为唯一最终结果）
- **同设备取代**：一次新发送开始（**新会话创建之前**）时，按对端身份移除该对端全部**已终态**会话的可见条目，避免同一设备同时出现「上一条终态条目 + 本次会话」
  并把上一条结果误认为本次结果。匹配规则以纯函数表达——双方 IP 均非空按 IP 相等、否则双方昵称均非空按昵称相等、否则不匹配（匿名/身份缺失的对端不参与同设备判定）。局域网发送以对端
  IP 与昵称声明身份，互传发送仅以昵称声明身份（协议载体不携带对端 IP），故按设备判定**跨协议**生效；移除的只是可见条目，任务历史照常保留，且不触碰非终态会话与其它对端
- **清除历史语义与置灰口径**：「清空任务历史」为不可逆操作，点击入口先弹 DialogV2 二次确认
  （`AlertDialogV2`、取消 / 确定两键；取消或点击弹窗外区域均不产生任何效果；说明文案经
  `views/transfer/ClearHistoryConfirmDialog.ets` 共享构造），确认后同时清空持久化历史、
  全部已终态可见会话条目与发送文本目录（best-effort），不触碰进行中与待确认会话；
  入口可用性以「可清除计数 = 历史条数 + 已终态可见会话数」为唯一依据，可清除计数为零才置灰，保证「清除后无残留」与「置灰状态与列表内容一致」
- **运行期完整记录**：会话创建时采集本机标识（昵称 / 主 IP / 网卡接口名，取启停过滤后的接口列表）；字节进度事件驱动峰值速度采样，终结时按总字节/耗时推导平均速度（不可得时为 0）；
  终结入口同时承载错误信息与错误码；**逐文件状态在唯一终结入口按终态类别补齐**——成功类全部置成功并补齐已传字节，失败/部分失败类已完成文件保持成功、
  其余（等待中/传输中）置失败，取消类已完成/已失败文件保持、其余（等待中/传输中）置「已取消」，拒绝类保持终态前原状，使终态结果与文件清单语义一致并随历史条目持久化
- **生命周期诊断**：会话创建（标识/协议/方向/阶段/文件数）、阶段推进（仅阶段跃迁，不记录高频进度）、终结（标识/结果/错误码/文件数）、回收（标识/结果/已归档）
  、同设备取代（被取代标识集合）以及详情页历史条目解析失败均输出可检索的结构化日志，使「会话从创建到消失」与「条目被判定为不可解析」均可事后还原

## 3. 协议会话标识与交互诊断

- **协议会话 ID 的语义与各协议取值**：统一会话的「会话标识」是应用内唯一事实源（列表条目身份、详情取数、去重/归档/回收），「协议会话 ID」
  （`TransferSession.protocolSessionId`）只承载**协议层会话标识**，供与对端核对、按协议事件对齐；协议层无此概念时为空（详情页以统一占位展示）。各协议取值：
  局域网接收为 `prepare-upload` 的接收方会话标识（真协议标识）；互传发送为协议任务标识；互传接收为请求携带的任务标识（缺失时回退固定常量）；局域网发送与网页下载为**空**。
  局域网发送的协议标识由 `prepare-upload` 握手后返回、创建时物理上不可知，故注册表提供「创建后回填」能力——仅空 → 非空、仅非终态写入、写入后发布变更通知；
  回填在拿到接收方标识后、会话终结之前完成，故归档值等于终态时刻的实际值（未回填则为空）。网页下载协议层为按浏览器的授权/快照缓存，任务身份为下载批次 `batchId`，
  不上屏。**应用内部业务编号**（如局域网发送的 `multi_<时间戳>_<序号>`）只用于业务侧会话归属与残留进度清理，既**不作为协议会话 ID**、也**不作为取消目标下发**
- **发送侧交互诊断与能力边界**：发送过程留下可检索的阶段诊断——发起发送（对端/文件数/协议会话标识「尚未就绪」）、协议会话标识回填、对端已开始接收（由**首个发送方向进度事件**判定并标注为**推断**，
  每个会话最多一条，不记录逐条进度）、终态（结果 + 错误码）、无进展兜底终结（复用既有终结日志）、我方取消（实际下发目标 + 本地/远端下发结果；取不到协议标识则不下发并留痕）
  、原生错误事件（已订阅，结构化记录，可归属时关联会话）。取消目标只能是协议标识。**能力边界**：对端「接受/中止」在当前应用层只能是推断信号（首个进度事件/返回码）——
  确定信号需原生层新增事件，列为后续工作，本轮不含原生改动；接收侧的会话结束事件按方向过滤，仅当标识确属本机接收会话时才生效，发送方向或陌生标识的同类事件忽略并留痕

## 4. 文本与文件

- **文本即文件（文本统一落盘）**：局域网/互传 × 发送/接收四条链路的文本内容一律落盘为**文件**，会话与历史不承载正文（正文只存在于文件与其路径）。
  目录与命名：**接收**文本落应用**私有持久目录**下的接收文本目录（`filesDir/text_recv/`，重名自动加序号、不覆盖）；
  **发送**文本落应用**私有持久目录**下的发送文本目录（局域网手输文本与互传发送文本均写 `filesDir/text_send/`，路径统一由 `SendRepository.sendTextDir` 提供；
  接收文本目录由 `ReceiveTargets.recvTextDir` 提供；两目录均不在冷启动清理范围内，只在用户主动「清空任务历史」时被清空，故文件留存与清除完全由用户可控；未发起发送的暂存文本仍按暂存规则清理）。
  收发文本的文件名仅为内部实现细节，UI 不向用户展示（列表与暂存行改用「文本」标签）。
  协议行为不变：互传保持文本通道与文本条目、局域网保持文本预览语义，落盘只是本地多一步持久化
- **逐文件路径贯通会话与历史**：会话文件条目与历史逐文件条目各带**可选路径**——接收侧由接收目标解析结果经运行期入口在会话终结前写入，发送侧由发送条目写入，归档时透传。
  该字段是详情页读取文本内容的唯一依据；**历史条目转为详情文件条目时路径同样透传**（会话离开运行时注册表后仍按历史条目携带的路径读取内容），无路径（旧数据、异常时序）
  时按「不可用」降级，不抛异常。文件级接收历史只存路径与元数据：正文不再写入偏好存储，查看全文/复制改为读取文件本身，删除条目（含清空）时文本文件与普通文件一致删除
  旧版 Web 上传路径曾把文本消息正文写入 `ReceiveHistoryEntry.textContent`；读取时检测到该字段即剥离并全量回写一次，之后不再产生
- **文本预览的文本消息判定**：详情页文件区块的「仅一个文本类文件 → 内联预览」在形状判定（`decidePreviewMode`，纯函数不变）之上增加会话语义守卫——
  只有会话显式标记为手动输入的文本消息（`TransferSession.textMessage`，由协议适配器在创建时声明）才内联预览；文件选择器选中的 `.txt` 等文本文件
  按普通文件清单呈现（可点击预览），不再显示「来自某设备的文本」。历史态取归档的 `SessionHistoryEntry.textMessage`；旧条目无该字段时按应用私有文本目录
  （`sendTextDir` / `recvTextDir`）路径兜底，避免误判。该判定同时消除待确认/进行中阶段无内容占位条目被误判为内联预览而显示「内容不可用」的误导
- **详情信息的实时 / 归档双口径**：详情页完整信息（`SessionDetailMeta`）由实时会话与持久化历史条目**统一取数**，可变字段以 `@Trace` 承载并在刷新时**原地更新同一实例**。
  耗时与平均速度在**进行中按实时口径**——耗时 = 当前时刻 − 开始时刻、平均速度 = 已传字节 ÷ 已用时间、峰值速度取会话实时峰值；会话进入终态后**回落归档口径**——
  耗时取会话耗时、平均速度取归档平均速度，保证「实时浏览结束后」与「之后从历史条目进入」看到同一个值。待确认阶段（未开始计时）或从未产生字节进度时保持统一占位符，
  不显示 0、不虚构值；刷新跟随既有的进度变更通知节奏，不引入独立定时器
- **文本接受的命名**：文本消息接收的正向动作是「接受文本」（不进入下载流程，剪贴板写入由 UI 侧在用户选择「复制」时独立完成）。该链路按此语义统一命名——门面 `MtaRepository.acceptMtaReceiveText`、
  接收动作注入入口参数 `acceptText`、适配器内文本内容存储 `textContentByUnifiedId`；展示文本预览相关命名（`textPreviewByProtocol` / `textPreview`）确为「文本预览」语义，不在统一范围内
- **文本消息与相册入口**：
  - 文本消息的文本内容由 `ReceiveRepository` 摄入请求时取自待处理请求的 `preview`（仅手动输入文本带该字段），写经
    `ensureReceiveSession` 进入适配器侧映射，展示描述符据以携带文本内容（`supportsTextPreview` + `textPreview`）
  - 详情页渲染文本预览卡片（可滚动文本 + URL 时「打开链接」），与任务列表行的文本会话动作一致，均为「关闭」+「复制」：关闭＝直接触发接受，
    复制＝写入剪贴板成功后触发接受（复制内容文件优先、描述符兜底，文件读取按缺省 200KB 上限截断并提示，与多文件清单/接收历史同口径）；接受经适配器回接受 ack，
    落盘完成通知回填真实路径后按成功收尾（不进入下载流程），剪贴板写入为 UI 侧副作用，与协议接受正交；
    文本会话判定由适配器在创建时声明的 `TransferSession.textMessage` 与展示描述符（`supportsTextPreview` + `textPreview`）共同承载：
    前者区分手输文本消息与 `.txt` 等文本文件并随历史归档，后者提供正文预览内容；详情页与列表行共用同一口径，列表行模型在构建期预计算该标志
  - 文件接收会话以 `canSaveToGallery` 声明相册能力，完成态的标题栏菜单次级入口经 `getGalleryMediaFiles` 取媒体文件交由 `GallerySaveService` 保存

## 5. 任务历史（SessionHistoryStore）

`SessionHistoryStore` 以**抽象存储接口** + `PreferencesUtil` 实现（独立存储文件 `handysend_session_history`；分段 JSON、有界 FIFO、`schemaVersion`、按会话标识幂等归档）；与文件级接收历史相互独立。

- 归档规则：所有终态会话统一归档，包含待确认阶段被拒绝、或因对端撤回/本机待确认超时而终结的会话，保证终态可见窗口结束后仍有唯一可进入的历史条目；归档调用为单入口且不携带「终结前是否待确认」参数
- 历史条目字段：既有字段外扩展对端设备信息（指纹 / IP / 类型 / 型号、MTA 品牌标识 `peerMtaBrandId`〔可选，缺省按非
  MTA 降级〕）、逐文件清单（含校验和与终态阶段，阶段取值含「已取消」）、文本消息标记 `textMessage`（可选，旧条目缺省按非文本消息降级）、
  耗时、平均/峰值速度、错误信息与错误码、完整时间线与本机标识；
  读写统一按当前版本处理，不实现版本迁移（读取不校验版本，可选字段对旧条目天然容错）；时间线持久化设容量上限（`SESSION_HISTORY_TIMELINE_CAPACITY`）
- 归档时的时间线按**落盘形态**写入（`persistedTimelineOf`），只保留展示与读侧实际消费的「事件类别 + 时间戳」。逐事件重复存储的会话标识在所属条目上已有一份，`detail` 无任何消费者，二者按事件数成倍放大持久化体积；内存中的活跃会话时间线不受影响，旧条目仍带这两个字段，读侧忽略即可
- Preferences 实现以**内存权威列表**承载读取：首次访问时从偏好存储加载一次，`persist`/`clear` 先更新内存再触发落盘（沿用偏好存储的防抖刷写），读取直命中内存，
  避免传输中进度事件高频触发中心刷新时反复同步读 + 全量 JSON 解析；读取链路做**读取即自愈**——`sanitizeHistory` 按会话标识去重（同标识保留 `finishedAt`
  最新一条）、聚合字段（`fileCount`/`totalBytes`）以逐文件清单为准重建、空清单脏条目剔除，并按硬上限裁剪超限旧数据；
  清洗/裁剪结果回写持久化，既有污点数据一次性修正；回写仅在清洗/裁剪
  **确有改动**时执行（`isSameEntries` 按同引用与同序比对，未受影响的条目保持原对象引用），使健康数据不必每次冷启动都全量序列化覆写一遍；`clear`
  为破坏性操作，写入空表后立即 `flushNow` 落盘，避免防抖刷盘窗口内进程被杀导致冷启动后历史重现；`resetSessionHistoryCache()` 供测试与重置场景失效缓存
- **分段存储**（段键布局与纯逻辑见 `model/HistorySegments.ets`）：偏好存储只能按键整体覆写，单键方案每次写入都要序列化全量历史，代价随保留条数线性增长。
  故把集合切成若干段分键存放——段键为「`transferSessionHistory#<段号>`」，段号自 0 连续且**递增表示更新**（0 最老）；
  写入只追加/覆写目标段，裁剪后删除尾部残留段，故无需额外索引键；
  任务历史未超过硬上限时新增条目只重写当前活跃段；超过硬上限（1000）时一次性裁回目标 750，
  全量重写约每 250 次追加发生一次，不再每追加一条就整体左移。裁剪按条数保留最近目标容量，
  随后按固定段大小重新切分；目标容量与硬上限均为段大小的整数倍（任务历史 750 = 250 × 3、1000 = 250 × 4；
  接收历史 5000 = 250 × 20），故保留结果由整段组成，无需段内处理。
  任务历史读取/清理按旧布局的 8 段探测；加载时仅在超过硬上限时裁剪到 750，并删除目标段数之后的残留段
  （旧 8 段布局下即 3–7 段），避免降低容量后丢失最新的旧段。
  归档落盘记录批量裁剪条数与慢写入耗时（≥50ms），用于判断是否还需要环形段/绝对段号。
  分段之前的单键历史由一次性迁移接管：老键存在即读出切段写入后删除，老键即迁移标记，单向且幂等，删除后该分支不再命中。
  读取全部分段的入口是唯一的，换存储层时按同一键布局契约实现即可
- 保留容量：任务历史目标 750 条（`SESSION_HISTORY_CAPACITY`）、硬上限 1000 条（`SESSION_HISTORY_MAX_ENTRIES`），
  接收历史 `RECEIVE_HISTORY_CAPACITY = 5000`，均定义于 `model/HistoryCapacity.ets`（两类历史同处一个事实源）。
  任务历史按**会话**计数、接收历史按**文件**计数，两者独立裁剪、不相互换算。一次传输产生 1 条任务历史却产生 N 条接收历史：
  100 文件批次下任务历史覆盖 750–1000 次传输（裁剪后回落到 750），接收历史只覆盖 50 次，
  故接收历史定位为「最近文件快捷入口」而非完整传输档案；
  接收落盘文件另有两处更长期的入口（文件本体所在下载目录、任务历史的会话详情），接收历史被裁剪不构成文件丢失
- **内容版本号** `getHistoryRevision`：进程内信号、不参与持久化，仅在持久化内容可能变化时自增（归档、清除、按标识删除、读取时清洗确有改动而回写）。
  任务列表在传输中被进度事件高频刷新，而历史条目在这些刷新之间完全不变，版本号未变即跳过历史行重建（详见
  [ARCHITECTURE.md](../ARCHITECTURE.md) 任务页行为细节）

## 6. 协议适配器

- **协议适配器契约**：`adapters/SessionAdapter.ets` 定义 `SessionAdapter`（能力声明、展示描述符、确认/拒绝/取消/重试、事件翻译、会话资源释放）
  与适配器注册表；可选成员 `getGalleryMediaFiles(sessionId)` 由适配器提供该会话可保存到相册的媒体文件（未实现或未提供时页面回退到既有接收媒体信号）
  - 现有六个适配器：`LocalSendSendAdapter` / `LocalSendReceiveAdapter` / `MtaSendAdapter` / `MtaReceiveAdapter` / `WebDownloadAdapter` / `WebUploadAdapter`，另有最小桩 `StubAdapter` 验证扩展点
  - 待确认阶段的接收侧超时：LocalSend 接收与 MTA 接收各 60 秒；Web 上传待确认 60 秒。
    下载已无待确认，浏览器会话只有 2 小时绝对 TTL；下载批次由服务端写超时/取消收口；MTA
    超时按已取消终结统一会话并复用拒绝入口释放接收侧资源（关闭连接、复位到可继续接收），阈值长于对端 35 秒接受窗口，避免抢在对端仍等待时误终结。
    MTA 服务侧等待用户确认的超时为 30 秒；服务复位到 `SERVICE_RUNNING` / `IDLE` 时，适配器立即把仍待确认的会话按已取消收口，
    适配器 60 秒定时器仅作服务无响应时的兜底
  - 互传接收的完成回填（`MtaReceiveAdapter`）：接收请求到达时协议只提供主文件名与文件数量，故创建单条占位条目（多文件时主文件名后追加省略号、
    单文件保持主文件名，下载完成后被真实清单取代）。占位条目的文件标识取 `mta-main`，与真实条目标识 `mta-<i>` 不相交；详情页文件条目循环键为
    `fileId + '#' + occurrence`，回填前后键集合不相交，故被替换的行必然重建并读取真实名称/大小——**会话文件条目循环键唯一性**不变量：
    占位条目标识与真实条目标识不得重合，同一会话内键唯一（否则该行复用旧节点而继续显示占位条目的主文件名与整包声明总量）。
    下载落盘完成（`COMPLETED`）时，以状态快照中的逐文件元数据（`receivedFiles`：名称/大小/真实类型）
    与逐文件路径（`savedFiles`，与 `receivedFiles` 按下标一一对应）组装描述符（`fileId`=`mta-<i>`、类型缺失按文件名扩展名兜底）经 `setSessionFiles`
    整体替换占位条目后按成功终结；路径随描述符写入，归档时由逐文件条目透传，故实时终态可见期与历史只读态的条目数/名称/大小/路径一致。
    失败/取消/拒绝路径不触发回填；互传原生文本消息不经下载流程（无 `COMPLETED`），其落盘完成通知先回填真实路径、
    再按成功终结会话，保证归档条目与详情页预览不因提前归档而缺路径
  - 展示描述符的 `directionLabel`、对端名称与副标题（`peerTitle` / `peerSubtitle`）及会话离散阶段文案（`TransferSession.stageText`，MTA 各阶段文案）以 `ResourceStr` 承载并配三语言资源，随系统语言切换
  - 描述符另携带对端 `deviceType` 与可选 `mtaBrandId`：`mtaBrandId` 存在即表示对端为互传（MTA）来源，设备卡据此渲染品牌彩色图标（-1 为未知品牌，回退默认 MTA 图标），
    否则按 `deviceType` 渲染设备类型图标（缺失或未知回退手机）；该规则与发送页设备列表同源（`DeviceIconUtil.getPeerDeviceIconResource`），保证同一设备两处图标一致。
    MTA 协议载荷（BLE 广播、GATT DeviceInfo、sendRequest）不携带对端设备类型或型号，MTA 会话的 `deviceType` 恒回退手机图标，适配器不伪造设备类型；MTA 发送的 `mtaBrandId`
    取自发送请求的品牌标识、MTA 接收恒为未知品牌（-1），并随会话与历史归档，保证设备卡图标在会话进行中与结束后不变。设备卡标识区复用对端 `fingerprint` 字段承载标识—
    —MTA 会话写入对端 BLE 设备地址（发送侧取发送请求、接收侧取已连接 GATT 对端标识并回退发送方 ID，皆不可得时按不可用降级），无 LocalSend 指纹时在该区展示；
    标识行标签随来源切换（MTA 用中性文案 `device_identifier_label`，其余沿用 `device_fingerprint_label`），交互与指纹行一致（默认缩略、点击弹出完整内容、弹窗内长按自由复制）
- **MTA 发送的代次守卫与实例生命周期**（`MtaSendAdapter` / `MtaSendService`）：每次发送单调递增「发送代次」，并为该次发送新建独立事件处理器（捕获本次代次与本次请求）
  ；状态事件入口按代次过滤，非当前代次的事件一律丢弃（不创建会话、不改变当前状态、不影响后续发送），判定同时覆盖「创建会话」与「更新/终结会话」两侧。
  会话创建只使用本次请求信息；终态事件只终结已存在的会话，不作为会话的诞生事件。发送服务释放时置空事件回调，实例被释放后不再向适配器投递任何状态。
  实例结束的两个动作按职责拆分并各自可判定——接收服务记账恒归还一次（收发互斥计数不泄漏），资源延迟回收仅当前代次可安排且在触发时再次校验代次（旧实例不得销毁当前生效实例）
  ；新发送开始会取消上一实例挂起的回收。上述判定抽为可导出纯函数（`decideMtaSendEvent` / `decideMtaSendInstanceEnd`），竞态可在设备端用例中确定性复现，不依赖真机多次发送
- **完成信号与路径顺序**：`SessionAdapter` 只统一协议翻译与动作分发，不统一「什么事件代表完成」。每个适配器/仓库须保证成功 `finish`
  前最终路径已写入统一会话：LocalSend 接收在 `acceptWithTargets` 预创建目标时写入、全部文件传完后终结；Web 上传在 `UploadDone`
  事件回填后经 `allDeclaredFilesDone`（要求每个文件 `path` 非空）终结；Web 下载建会话时即从分享档案携带源路径；互传文本在落盘
  完成通知回填真实路径后终结。新增协议若自行合成文件，不得以用户接受等动作替代完成信号，并须补充「归档条目带路径」的设备端用例

## 7. 三类注册表

默认注册集中在 `DefaultRegistrations.ets`：

- `DeviceSourceRegistry`：设备来源（标签/图标/排序/发现数据源/空态与条件化引导/是否收藏）
- `TransferMethodRegistry`：方式（网页传输/指定 IP，按「网页」与「其它方式」分组）
- `SettingsGroupRegistry`：设置分组（通用组与协议组按同一 `order` 序列混排，新增协议只需注册自己的分组）
- 来源空态描述支持可选 `dynamicText()` 动态文案（设置后优先于静态 `text`），如 MTA 蓝牙关闭时切换为开启蓝牙提示

## 8. Web 分享链路

- **Web 下载任务模型（下载批次）**：单文件一批、多文件一个 zip 批，一个批次一个任务；
  批次开始/结束由 `WebDownloadStarted` / `WebDownloadEnded` 驱动，取消按 `batchId` 停止响应。
  网页访问不建任务，只记日志并续期网页保活；页面不做下载进度轮询。
  批次内文件按条目事件逐个完成，批次结束由服务端终态收口；页面关闭不影响已在传输的响应。
  匿名对端以客户端 IP 作为展示名兜底（不拼接本地化前缀，
  副标题不重复该 IP，网页来源由来源徽标表达）；会话文件取事件携带的真实文件名并据此推导类型，分享期间经「分享文件档案」（`fileId` → 真实文件名/类型/本地位置）
  回填本地内容位置，仅文件表显式携带 `preview` 的手输文本消息展示文本预览（普通 `.txt` 文件不按文本消息处理）；同 IP 终态后再次下载创建新会话
- **页面门禁通过即下载授权**：扫码或本次访问码任一通过，prepare-download 直接回文件表；
  应用侧只记访问日志并续期网页保活，不建任务、不弹提示。无门禁仅测试/旧调用放行并告警。
  地址与二维码携带本次服务实例的能力令牌，用于换取绑定 IP/UA 的 HttpOnly Cookie；裸地址展示访问码页。
  访问码每次服务启动生成（6 位数字），分享停止或服务重启即失效；兼容配置下令牌只做页面准入，
  不替代逐次确认（令牌可被转发/截图，绑定强度不足以承担外发授权）。
  网页下载批次/上传任务声明 `canCancel`；下载取消按 `batchId` 停止响应，上传取消移除服务端会话；
  正在传输的响应在下个读块停止。
- **网页批次状态**：下载在首个 body chunk 后进入「传输中」，批次结束/失败/取消由服务端事件收口；
  上传确认后显示「等待上传」，首包到达后进入「传输中」。网页下载/上传的结束动作显示「结束下载/结束上传」，
  不再把结束批次误称为结束整个网页访问。
- **网页来源会话的展示归一化**：浏览器上传产生的入站会话在**摄入层**（`LocalSendReceiveAdapter`）归一化展示——对端设备类型为 web 时以客户端 IP 作为对端名称、清空型号徽标；展示描述符在标题已等于 IP
  时把副标题置空，不重复展示同一 IP。非网页来源（普通 LocalSend 设备）会话保持对端真实别名与型号徽标。来源徽标按「协议键 + 对端设备类型」解析（`TransferCenterViewModel.sourceLabelForSession`）：对端
  设备类型为 web 的会话（含走局域网接收协议的浏览器上传）统一显示网页来源标签，其余沿用按协议键解析，故普通 LocalSend / 互传来源不受影响；任务中心实时行/历史行与详情页（实时与历史摘要）同源同口径
- **网页面板启停与布局**：`ShareLinkViewModel` 由网页传输总开关经变更总线派生 `sendDisabled`，并同步允许上传子开关；
  `ShareLinkPage` 以总开关为唯一启停态：关闭时页面中部提示服务已关闭、底部给出开启按钮；开启时顶部按需出示警告横幅、
  顶部依次出示警告横幅、访问码组与二维码组，底部出示允许上传、上传免确认与停止按钮。面板按钮写回总开关与允许上传子开关，与设置页双向同步；冷启动由主页启动流程
  调用 `restoreWebService()` 按开关恢复服务，停止 LocalSend 服务器不联动停止网页服务，面板返回也不停止服务
- **网页分享加密场景提示**：`ShareLinkViewModel` 在加载分享信息时由网页独立加密开关（`getWebHttpsEnabled`）派生只读提示状态。
  加密开启时 `ShareLinkPage` 在页面顶部渲染纯文字提示条，说明网页分享使用自签名证书的加密连接、部分浏览器扩展或安全策略
  可能拦截下载，如遇无法下载可关闭加密传输或调整浏览器扩展/设置；未挂载分享文件时该位置改为无文件警告（两者互斥）；
  关闭加密时不渲染。提示条复用 `warning_bg` 背景与 `warning_orange` 文字及设计令牌，不含可执行操作，不遮挡地址、二维码与底部启停按钮，
  对应三语言资源键 `web_share_https_hint`
- **网页访问码锁定与会话结束**：访问码错误达到上限时服务端回 429 并携带 `Retry-After`，页面按剩余秒数倒计时并暂时禁用输入；
  应用结束任务或服务端超时回收会话时经 SSE 推送结束事件，页面立即进入“本次访问已结束”状态，无需等待心跳/轮询
- **网页页面生命周期**：下载不再有心跳/leave/下载 session-end；上传页关闭经 `/web/leave` 进入 15 秒宽限，
  上传进度会取消关闭标记。文件表变化经 SSE 通知后静默重拉完整列表，实时更新并短暂提示「文件列表已更新」；
  15 秒 `/caps` 轮询兜底。停止分享先标记 stopped 并保留服务约 30 秒供页面收尾/刷新，再关闭监听。
- **网页独立设置**：`WebSettingsSection` 提供网页传输总开关、允许上传与高级设置折叠（加密传输、端口与网络接口）；
  访问码不进入设置页，由分享面板在每次服务启动时生成并展示（6 位数字，裸地址手动输入时使用）；
  面板提供与暂存文件列表解耦的“上传免确认”（默认关闭）；重新进入面板、撤下文件与就地换表均保留，
  仅在应用重启或手动停止网页服务后重置。
  新装默认加密关、接口按类型默认（Wi-Fi/有线/VPN 启用，蜂窝/网桥/未知关闭）、端口 53310。
  网页加密传输与 LocalSend 加密传输互不影响，不会从 LocalSend 继承；
  修改加密传输/端口需要重启网页服务，有活跃网页会话时先二次确认，确认后中断会话并重启
- **网页网络接口与端口**：服务监听 `0.0.0.0`，不按网卡拆监听；`WebAddress` 纯函数从本机接口中筛出可用 IPv4，
  按优先级排序并按 IP 去重。设置页“网络接口”多选列出全部可用 IPv4 接口，白/黑名单与 LocalSend 同口径
  （黑名单优先，未列出的按类型取默认，蜂窝/网桥/未知默认关闭）；仅影响展示地址，不限制实际监听/访问，半屏弹窗与 LocalSend
  网络接口弹窗同款布局（类型图标、接口名 + IP、刷新与保存）；面板在多地址时于地址胶囊下方
  提供“网卡类型 + 下箭头”轻量选择器，菜单列出类型与 IP，当前项带勾选，选择按 IP 持久化。端口默认 53310（预留 53310-53316），
  启动时优先复用本次进程内上次实际端口，其次配置端口，被占用时回退随机端口；同端口重建先停旧实例并等待监听套接字释放，
  避免被自己占住而误回退。实际端口不持久化，应用重启后重新优先尝试配置端口，回退时面板顶部提示
- **分享文件挂载不重启服务**：网页服务运行中选择或更新暂存文件时，`createShareLink` 走就地换表
  （`update_web_service_files`），保留端口、已打开的网页与进行中的上传入口；只有服务未运行或修改加密/端口
  需要应用新配置时才重建服务
- **网页面板与 LocalSend 开关解耦**：面板禁用态只看网页传输总开关，LocalSend 总开关不再影响地址、二维码与入口可用性；
  发送页网页图标直接进入统一面板，总开关仅决定进入后是出示服务内容还是已关闭提示
- **下载内容下发的长度一致性**：下载响应的 `Content-Length` 由上游按 `FileDto.size` 固定写入，响应体为流式内容源；实际交付字节少于声明大小时客户端立即中断下载（多于声明大小时被截断）
  。故内容源必须完整交付声明字节：fd 内容源以 `pread` 显式偏移读（副本与原始 fd 共享 offset，避免重复/并发下载读到空内容或交错数据），
  支持同一文件的重复与并发下载。宿主 HTTPS 集成测试（服务端启用 TLS + 接受自签名证书的标准客户端）验证大文件、重复与并发下载均逐字节完整，即
  TLS/响应下发路径本身无缺陷；浏览器侧无法下载由浏览器扩展或浏览器安全策略拦截所致（DevTools 显示 `net::ERR_BLOCKED_BY_CLIENT`，无痕模式可正常下载），与本机服务无关

## 9. 详情页与接收历史页的公共能力

会话详情页与文件接收历史页面向同一批文件与同一批操作（预览、打开位置、交给其他应用），共用的展示与交互能力收敛为**单份实现**，调整时改一处即两页同步生效：

| 公共能力 | 形态 | 位置 |
|---|---|---|
| 类型图标区 + 媒体缩略按需加载 | `@ComponentV2`（条目出现时懒加载一次、失败回退类型图标） | `components/FileEntryThumb.ets` |
| 单行缩略值行 + 点击弹窗 + 长按复制 | `@ComponentV2`（值为空则不渲染） | `components/SingleLineValueRow.ets` |
| 条目操作菜单项集合 | 选项结构 + 全局 `@Builder`（调用方以 `Menu()` 包一层） | `components/FileEntryActions.ets` |
| 文本预览阈值与可预览性判定 | 纯函数模块（无 UI、无状态） | `utils/FilePreviewPolicy.ets` |
| 保存到相册可用性与已保存状态 | 纯函数模块（媒体类型 + 定位来源判定；按接收历史标记与路径匹配） | `utils/GallerySavePolicy.ets` |
| 文件定位归一与打开能力 | 纯函数 + 系统能力封装（按来源类别判定可用性与存在性、返回结果态） | `utils/FileLocationUtil.ets` |

- **菜单归属与追加**：公共菜单项为「预览全文 / 打开所在位置 / 用其他应用打开 / 保存到相册」，
  另有可选「复制」项（会话详情文件清单使用：文本类且定位非空即展示，不受预览阈值限制；读取按缺省上限截断，超限明确提示截断），
  可用性由「类型 + 定位 + 来源 + 大小」判定
  （图库来源条目与应用私有文本的「打开所在位置」置灰——前者无文件管理器可导航目录，后者为应用私有目录；
  「用其他应用打开」走应用文件分享机制，沙箱自有文件属可分享目录，不受影响）；
  「保存到相册」仅接收方向已成功落盘的图片 / 视频且非图库来源时展示，已保存过时保留该项但置灰为「已保存到相册」——状态按接收历史的 `savedToGallery` 标记与文件路径匹配；
  点击时探测源文件，缺失则提示「文件已被移动或删除」并中止（与「打开所在位置」同口径）。应用未申请相册读取权限，不检测相册副本是否被用户从图库删除；
  各页在组件内以 `Menu()` 包一层后绑定到行上，接收历史页在末尾追加本页专有项（复制文本、删除记录），不另行实现公共项
- **阈值与读取口径同源**：预览阈值（128KB，回退值 64KB）同时作为预览场景的文本读取上限，经 `utils/FileTextUtil.readTextOfLocation` 的可选上限参数传入，
  避免「判定用阈值、读取仍按旧上限」的分叉；大小不可得（为 0 或未知）按可预览处理，不因缺信息而误禁
- **文件定位归一与打开路由**：沙箱绝对路径经 `fileUri.getUriFromPath` 得对外 URI；文件选择器返回的 `file://` 形式经 `fileUri.FileUri(...).path` 取本机路径，
  解析失败视为不可定位。图库来源（媒体库图片 / 视频标识 `file://media/Photo/...`，属虚拟路径、无文件管理器可导航目录）单独识别：
  不产出本机路径，存在性按资源标识打开校验；「打开所在位置」经 `openContainingFolder` 直接定位目录，
  图库来源（经 `isGalleryLocation` 判定）无文件管理器可导航目录、该项在菜单层置灰不可用，其余来源仍经系统文件管理器定位目录。
  「用其他应用打开」以隐式 Want（查看数据 action + 文件 URI + MIME 类型 + 只读授权标志 + 强制展示应用选择器）调起系统应用选择框，
  MIME 缺失或为通用二进制时按文件名扩展名推导（类型与 URI 不一致会导致系统匹配不到应用）；无可用应用 / 调起失败 / 用户取消 / 定位不可转授一律以明确提示收口。
  已知限制：文件选择器返回的 `file://` 定位，其临时授权通常无法转授给第三方应用，此时以失败提示收口
- **只读授权**：对外分享仅授予读取权限，不授予写入，且不新增权限申请
- **边界**：接收历史页只对齐预览与条目操作口径，不改列表结构、虚拟滚动与 `cachedCount` 约定，也不改其专有流程语义
  （复制文本、删除记录、清空历史及其确认弹窗）

## 10. 前台新传输提示

应用在前台时收到新的待确认接收请求，不再自动跳转详情页，而是在**当前任意页面（含子页面）之上**弹出统一的新传输提示弹窗：

- **触发源与去重**：`MainTabViewModel` 订阅变更总线，刷新时比对待确认会话集合（`knownPendingIds`），出现新标识时置位一次性信号
  `autoOpenSessionId`；同一会话最多提示一次（确认/拒绝后消失不再触发）
- **弹窗落点**：宿主为主页根容器 `MainTabFloating`，以组件内 `@Builder` + `AlertDialogV2` 经
  `getUIContext().getPromptAction().openCustomDialog(...)` 打开——`UIContext` 级自定义弹窗浮于整个窗口之上，与 `Navigation` 路由栈相互独立，
  故子页面亦可正常显示（不使用全局 `@Builder` 经 `openCustomDialog` 打开 DialogV2，规避上下文缺失导致的闪退）
- **单槽位守卫**：打开前同步置位「在场标记」，关闭（`onDidDisappear`）或打开失败时复位并再次尝试消费待提示信号，
  保证同一时刻仅一个弹窗且不丢失未提示请求
- **动作**：「查看」推入该会话详情页（`pushPathByName('SessionDetailPage', { sessionId })`）；「拒绝」直接按拒绝收尾并释放单会话槽位；点击遮罩/返回键仅关闭，会话保持待确认，仍可在任务中心处理
- **前后台边界**：应用处于后台时不弹、也不消费信号；回到前台（`onPageShow`）补弹一次
