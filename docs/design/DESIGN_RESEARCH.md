# HandySend 设计与现代化研究

> 为「多协议统一传输会话管理」特性重定范围提供依据。覆盖三块：① 会话管理与信息架构、② 诊断与故障排查、③ 现代化 UI/UX。
> 结论摘自竞品研究、现代架构模式与 HarmonyOS 官方最佳实践（见文末引用）。

## 1. 竞品分析

### 1.1 局域网 / P2P 传输类

| 产品 | 首页信息架构 | 是否有任务中心 | 进度呈现 | 历史 | 多协议 |
|------|--------------|----------------|----------|------|--------|
| LocalSend | 「发送/接收」分区 + 附近设备列表 | 否 | 即时弹窗/会话页 | 无 | 单协议 |
| Apple AirDrop | 系统分享面板 → 附近设备 | 否 | 系统进度胶囊 | 无 | 系统级 |
| Google / Samsung Quick Share | 分享面板 + 「已接收」历史页 | 否 | 通知 | 「已接收」独立页 | 多（Nearby/蓝牙/WiFi） |
| Windows 就近共享 | 设置开关 + 通知 | 否 | 系统通知 | 无 | 单协议 |
| 华为分享 | 系统分享面板 + 进度胶囊 | 否 | 胶囊/通知 | 无 | 系统级 |
| KDE Connect | 设备列表（配对为中心）+ 插件 | 否 | 插件内 | 无 | 插件式多能力 |
| Snapdrop / PairDrop | Web 房间式极简 | 否 | 页内进度 | 会话内 | 单协议 |
| SHAREit / Xender | 功能宫格首页 + 传输列表 | 半（传输列表） | 页内列表 | 有 | 多 |
| 微信文件传输助手 | 会话式（聊天即传输） | 否 | 聊天记录 | 聊天记录 | 单协议 |
| Warpinator | 设备列表 + 传输进度列表 | 半 | 列表 | 无 | 单协议 |

**共性结论**

1. 这类工具**普遍没有「任务中心」**：传输多为短时动作，由系统通知 / 进度胶囊承载。
   → HandySend 引入任务中心是**「下载管理器化」的差异化做法**，其价值只在**多会话并发 + 多协议并存 + 历史回溯**时成立。因此任务中心必须做对：信息层级清晰、状态可辨、可回溯、可操作；否则不如一条通知。
2. **成功产品的核心都是「选设备」**，功能宫格是次要入口（SHAREit 的宫格是反例：信息密度高、发现动作被淹没）。
3. 「历史」普遍是**独立的「已接收」页**。本设计中**任务历史（会话维度）与文件历史（文件维度）分离**是合理的，但必须在界面上让用户理解两者的区别与归属。

### 1.2 下载管理器 / 任务中心类

| 产品 | 借鉴点 |
|------|--------|
| Android Chrome 下载页 / DownloadManager | 列表项层级、按时间分组、失败重试 |
| IDM / Motrix | 多任务列表 + 队列 + 速度/ETA + 分类筛选 |
| qBittorrent / Transmission | 状态列 + 详情视图 + 批量操作 |
| 迅雷 | 任务中心 + 分类 + 详情 + 批量管理 |

**可借鉴的通用模式**

1. **列表项信息层级**：主标题（对端/文件）→ 元信息（方向、大小、来源）→ 进度与状态 → 尾部动作。
2. **状态即视觉**：颜色/图标区分进行中、成功、失败、已取消；失败项**一键重试**。
3. **分组与筛选**：进行中 / 待确认 / 已完成 / 失败；按来源或方向筛选。
4. **详情页**：会话摘要 + 文件清单 + 速度 / ETA / 剩余时间 + 动作区。
5. **空态**：插画 + 明确 CTA（而非一句提示）。
6. **速度/ETA** 是用户对「传输工具」的隐含期待（本项目已有 `SpeedEstimator`，可在会话详情复用）。
7. **批量操作**：全部取消 / 清除已完成。

## 2. 现代设计模式（架构层）

| 模式 | 说明 | 与本项目的关系 |
|------|------|----------------|
| **Registry + Adapter（端口/适配器）** | 协议差异收敛到适配器，核心引擎协议无关 | 本特性的核心抽象 |
| **显式状态机 + 单一事实源** | 会话生命周期由统一状态集合驱动，禁止旁路状态 | 替代当前各协议分散的裸字符串状态 |
| **单向数据流 + 只读视图** | 页面只读注册表快照，动作经命令回传 | 消除「页面各自算进度」 |
| **能力协商（Capability）** | 适配器声明支持取消/重试/确认/字节进度 | 驱动详情页动作可用性 |
| **可观测性优先** | 结构化日志 + 关联标识（sessionId）贯穿设备/会话/文件 | 直接衔接 ② 诊断特性 |
| **契约优先** | 跨层事件与接口有契约测试守卫 | 项目已有（NAPI 封装完整性 + 事件契约） |
| **渐进披露（Progressive Disclosure）** | 低频、复杂信息收进次级视图 | 会话详情、方式菜单、协议设置分组 |

## 3. HarmonyOS 现代化 UI/UX（官方最佳实践）

| 主题 | 要点 | 与本项目的映射 |
|------|------|----------------|
| **一次开发多端部署（一多）** | 直板机单列纵向 → 折叠屏/平板双列栅格 → 电脑「侧边栏 + 内容区」分栏；按断点切换 | 发送页「单栏 / 双栏」、任务列表密度、PC 分栏 |
| **分层架构** | products / features / common 三层，业务模块各自成 HAR，公共能力下沉 | 长期演进方向（本特性不强求工程改造） |
| **状态管理最佳实践** | MVVM，UI 是状态的函数；状态归属清晰、避免跨组件重复状态 | 会话注册表作为 SSOT，页面只读 |
| **长列表 / 网格性能** | 懒加载（LazyForEach）、渲染范围控制、Grid/List 复用与缓存 | 任务会话列表、任务历史、设备网格 |
| **沉浸光感 / 悬浮组件** | 标题栏/导航栏/工具栏的毛玻璃模糊、按压弹性光效、滑动透明度渐变；悬浮组件 | 任务入口角标、浮动操作栏、方式菜单 |
| **半模态面板（bindSheet）** | 轻任务 / 信息面板（分享、简介、创建） | 会话详情内的轻量操作、方式菜单、品牌选择（已有） |
| **实况窗 / 通知** | 后台长任务的进度与结果承载 | 已有后台传输通知；建议与会话中心一致口径 |

**要点提炼**

- **响应式是官方一等公民**：单列 → 双列 → 分栏是推荐路径，本设计的「单栏/双栏」与之吻合。
- **列表性能要按长列表对待**：任务历史可能累积到数百条，必须懒加载 + 渲染范围控制，否则与 ② 的日志页一样会卡。
- **悬浮与沉浸是 HarmonyOS 的视觉语言**：本项目已用 `HdsTabs` 悬浮样式，任务入口与浮动操作栏应延续同一套材质与动效。

## 4. 对 HandySend 的改进建议

按优先级给出，并映射到三个特性。

### P0（特性 ①：统一会话管理 + 信息架构）

- **任务信息层级**：会话条目 = 对端/文件名 + 方向与来源徽标 + 进度条/状态 + 尾部动作；进行中置顶，其次待确认，再次历史。
- **会话详情**：摘要 + 文件清单 + 逐文件进度 + **速度 / ETA / 剩余时间**（复用 `SpeedEstimator`）+ 动作区（确认/拒绝/取消/重试/存相册/验证，按能力声明）。
- **筛选与分组**：进行中 / 待确认 / 已完成 / 失败；按来源协议筛选。
- **空态体系**：无会话、无设备、无历史分别有独立空态与 CTA（设备来源空态由来源描述符提供）。
- **发送页三区 + 响应式**：内容 / 目标 / 方式；单栏整页滚动 + 内容可折叠，宽屏双栏。
- **设置分层**：通用组 + 协议组（注册表驱动）。

### P1（特性 ①）

- **批量操作**：全部取消活跃传输、清除已完成。
- **失败重试**：详情页一键重试（能力声明控制）。
- **会话时间线**：详情页展示关键事件（创建 → 确认 → 开始 → 完成/失败），为 ② 的诊断预留。
- **无障碍与热区**：沿用 48vp 热区规范，补齐会话条目的无障碍文本。

### P1（特性 ②：诊断与故障排查）

- **日志升级为可观测体系**：结构化字段 + **以 sessionId / 设备指纹 / 协议为关联键**贯穿；分级；按协议域过滤。
- **日志与会话联动**：从会话详情可直接跳转到该会话的相关日志（过滤到 sessionId）。
- **故障排查流程化**：现有 `TroubleshootPage` → 引导式检查（网络/权限/服务/协议）→ 直达 `HttpLogsPage`；提供一键导出诊断包。
- **性能**：日志页按长列表对待（懒加载 + 渲染范围控制）。

### P2（特性 ③：现代化 UI/UX）

- **视觉现代化**：延续 `HdsTabs` 悬浮材质，统一毛玻璃/按压光效/滑动透明度；关键转场用共享元素（一镜到底）。
- **多端细化**：PC/2in1 的分栏与自定义标题栏；平板双列；折叠屏展开态。
- **空态与动效插画体系**：统一空态、加载（骨架屏）、错误态的表达。
- **可选探索**：会话中心的桌面化（PC 分栏 + 多选批量）、导入/导出任务历史。

## 5. 结论

- **任务中心是本应用的差异化点，但只有「多会话 + 多协议 + 历史」都做对才成立**——因此 ① 的重点是**信息层级、状态可辨、可操作、可回溯**，而非单纯把进度搬到一处。
- **响应式（单列→双列→分栏）与长列表性能是官方推荐路径**，与本设计一致；须提前按长列表设计任务与历史。
- **可观测性（②）与本特性天然耦合**：会话标识应直接作为日志关联键，避免二次改造。
- **视觉现代化（③）应尽早输入 ①**，尤其是悬浮材质与动效语言，以免 ① 落地后再返工。
